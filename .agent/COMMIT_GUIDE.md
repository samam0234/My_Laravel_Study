# 커밋 가이드

형식은 <type>: <한글 설명>이며 type은 feat/fix/docs/refactor/chore/test/style을 사용한다.

1. 전체 검증과 노션 반영 후 study0~10, studyMidpoint, study11~18, studyFinal 순서로 커밋한다.
2. 각 진도 문서는 별도 커밋으로 만들고 관련 구현·테스트·설정을 함께 넣는다. 공통 인수인계·도구·의존성 정리는 별도 준비 커밋으로 묶을 수 있다.
3. 기존 study는 덮어쓰고 루트 학습 문서에는 study 접두사를 쓴다. README는 과정 안내다.
4. 민감값·생성 파일 제외, 관련 테스트·빌드·문서 코드 일치 검사를 확인한다.
5. 실제로 실행하지 않은 외부 연결을 성공으로 기록하지 않는다.
6. 사용자가 요청한 경우 origin 작업 브랜치에 푸시하고 확인한다. 강제 푸시는 사용하지 않는다.
